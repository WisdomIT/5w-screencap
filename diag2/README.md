# 2차 진단: screenrecord 대체 방법 확인

1차 진단에서 `screenrecord`는 실패했습니다. 등록된 H.264 인코더가 소프트웨어 인코더 하나뿐인데, 이 인코더가 Surface 입력을 지원하지 않기 때문입니다. 2차 진단은 직접 만든 녹화기로 대체할 수 있는지 확인합니다.

| 단계 | 확인 내용 |
|---|---|
| 1 | `/system/lib`의 TCC OMX 컴포넌트 이름과 하드웨어 인코더 흔적, `/dev` 장치 노드 |
| 2 | `/dev/graphics/fb0`를 직접 읽을 수 있는지와 그 속도 |
| 3 | `/system/bin/screenshot`의 동작 (바이너리를 복사해 PC에서도 분석) |
| 4 | Java 프로브(`app_process`): 코덱 전체 목록, 인코더를 이름으로 생성할 수 있는지, `SurfaceControl.screenshot` 속도, PNG/JPEG 압축 시간, **화면 → 인코더 → MP4 실제 녹화**(인코더별로 1280×480, 640×240, 1920×720 각 6초) |

## 실행
1. USB 루트에 `NEMESIS.data`, `5w_diag2.sh`, `5w_diag2.jar`를 둡니다.
2. 정차 상태에서 화면이 움직이는 상태(내비 주행 화면이나 CarPlay)를 띄워 둡니다. 녹화된 영상이 실제로 움직이는지 확인하는 용도입니다.
3. USB를 꽂고 **Yes**를 누릅니다. **최대 4~5분** 동안 조작하지 마세요.
4. "5W 2차 진단 완료" 토스트가 뜨면 끝입니다. 결과는 `5W-DIAG2-<시각>/` 폴더에 저장됩니다.

인코더 생성을 시도하다가 `mediaserver`가 재시작되면 소리가 잠깐 끊길 수 있습니다.

## 빌드
```bash
diag2/build.sh
```
JDK와 `.tools/r8-8.5.35.jar`(d8)가 필요합니다. `stubs/`는 컴파일할 때만 쓰는 android API 대체 클래스입니다.
